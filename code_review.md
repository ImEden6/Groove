### Phase 2: High-Level Review

#### Architecture & Design
- **Strengths:** 
  - Strict separation of musical meaning ([`Graph.java`](file:///D:/projects/Groove/core-engine/src/main/java/groove/engine/Graph.java)) from editor coordinates ([`EditorLayout.java`](file:///D:/projects/Groove/src/client/java/com/mervyn/groove/client/ui/EditorLayout.java)).
  - Immutable schedule snapshots ([`SessionTimeline.java`](file:///D:/projects/Groove/core-engine/src/main/java/groove/engine/SessionTimeline.java)) prevent concurrent modification during rendering.
  - Complete client/server authority separation: clients never transmit PCM over the network; only immutable, validated graph schemas and clock sync telemetry are shared.
- **Concerns:**
  - Missing UI instantiation pipeline for built-in synthesis nodes (`tone`, `euclid`, `fast`, `stack`).

#### Performance Assessment
- **Audio Rendering:**
  - In [`LiveRenderer.java:L51-55`](file:///D:/projects/Groove/core-engine/src/main/java/groove/engine/LiveRenderer.java#L51-L55), calling `sampleTimeline(...)` separately for each stereo channel duplicates oscillator calculation (`Math.sin`, `polyBlep`) and envelope calculations. At 48 kHz and 32 voices, this executes ~130,000 inner iterations per 42 ms audio block. Combining stereo channels into a single pass would cut transcendental math operations in half.
- **UI Drawing:**
  - [`ThemeDraw.java:L15-25`](file:///D:/projects/Groove/src/client/java/com/mervyn/groove/client/ui/theme/ThemeDraw.java#L15-L25) rasterizes lines and bezier curves using small `graphics.fill(...)` quads spaced every 2 pixels. While simple and portable, a 24-step bezier curve with glow and core strokes submits hundreds of quad draw calls per cable per frame. For larger graphs, baking cable geometry or using vertex buffers would eliminate this overhead.

#### Testing Strategy
- Core engine tests are robust and deterministic.
- UI interaction logic in [`InputController.java`](file:///D:/projects/Groove/src/client/java/com/mervyn/groove/client/ui/InputController.java) and [`EditorState.java`](file:///D:/projects/Groove/src/client/java/com/mervyn/groove/client/ui/EditorState.java) is completely decoupled from Minecraft and tested in [`BackendTests.java`](file:///D:/projects/Groove/src/test/java/com/mervyn/groove/music/BackendTests.java).

### Phase 3: Detailed Review & Findings

#### 1. Concurrency & Networking
- ℹ️ **`[verified-safe / retracted]` Thread-Safety in [`SampleLibrary.java`](file:///D:/projects/Groove/src/client/java/com/mervyn/groove/client/music/SampleLibrary.java#L27-L50)**
  - *Initial Concern:* Suspected cross-thread race conditions between Netty network thread and Minecraft main thread.
  - *Verification Result:* **False Positive.** Verified against Fabric API v1 source code (`fabric-networking-api-v1-1.3.11+1802ada577`). `ClientPlayNetworking.registerGlobalReceiver(CustomPacketPayload.Type<T>, ...)` automatically schedules incoming packet handlers onto the render thread (`client.execute(...)`). Therefore, packet chunk handling, client ticks (`END_CLIENT_TICK`), disconnect events, and state mutations to `failed`, `flight`, and `transfer` execute sequentially on the same main render thread. Off-thread decoding in `IO` schedules state commits back via `context.client().execute(...)`.
  - *Actual Technical Debt in File:* The file received a Grade B in Omen TDG due to high cyclomatic complexity (44) and deep callback nesting (9 levels), rather than threading defects.

#### 2. Logic & Error Handling
- 🟡 **`[important]` Potential NullPointerException in [`GrooveEditorScreen.java:L305`](file:///D:/projects/Groove/src/client/java/com/mervyn/groove/client/ui/GrooveEditorScreen.java#L305)**
  - *Location:* [`GrooveEditorScreen.java:L305`](file:///D:/projects/Groove/src/client/java/com/mervyn/groove/client/ui/GrooveEditorScreen.java#L305)
  - *Verification Result:* **Verified True.** `submit()` executes:
    ```java
    boolean playing = MusicClient.desiredState().playing();
    ```
    If `MusicClient.desiredState()` returns `null` (e.g. if the screen is initialized or active during connection resets before the first snapshot is received), this line throws an unhandled `NullPointerException`. In contrast, `reloadSession()` in the same file guards this with `if (desired == null)`.
  - *Recommendation:* Guard against `null` before sending:
    ```java
    var desired = MusicClient.desiredState();
    if (desired == null) { message = "Session unavailable; reload"; return; }
    boolean playing = desired.playing();
    ```

- 🟡 **`[important]` Unbounded Parameter Scrubbing in [`EditorState.java:L269-278`](file:///D:/projects/Groove/src/client/java/com/mervyn/groove/client/ui/EditorState.java#L269-L278)**
  - *Location:* [`EditorState.java:L269-278`](file:///D:/projects/Groove/src/client/java/com/mervyn/groove/client/ui/EditorState.java#L269-L278)
  - *Verification Result:* **Verified True.** Scrubbing values in the inspector (`dragValueTo`) adds raw deltas without clamping to the parameter’s valid range (e.g., gain `[0, 1]`, pan `[-1, 1]`, frequency `[20, 16000]`). The error is only surfaced later when `GraphJson.decode` throws an exception upon clicking Apply.
  - *Recommendation:* Clamp dragged values according to node and parameter type before updating node parameters.

#### 3. Code Cleanliness & Anti-Patterns
- 🟢 **`[nit]` Dead Template Mixins in [`src/main`](file:///D:/projects/Groove/src/main/java/com/mervyn/groove/mixin/GrooveServerMixin.java) and [`src/client`](file:///D:/projects/Groove/src/client/java/com/mervyn/groove/client/mixin/GrooveClientMixin.java)**
  - *Location:* [`GrooveClientMixin.java:L10-15`](file:///D:/projects/Groove/src/client/java/com/mervyn/groove/client/mixin/GrooveClientMixin.java#L10-L15), [`GrooveServerMixin.java:L10-15`](file:///D:/projects/Groove/src/main/java/com/mervyn/groove/mixin/GrooveServerMixin.java#L10-L15)
  - *Verification Result:* **Verified True.** Empty template mixins injecting into `Minecraft.run()` and `MinecraftServer.loadLevel()`. Safe to delete along with their entries in `modid.mixins.json` and `modid.client.mixins.json`.

- 💡 **`[suggestion]` Native Buffer Re-Use in [`GrooveAudioStream.java`](file:///D:/projects/Groove/src/client/java/com/mervyn/groove/client/music/GrooveAudioStream.java#L49)**
  - *Location:* [`GrooveAudioStream.java:L49`](file:///D:/projects/Groove/src/client/java/com/mervyn/groove/client/music/GrooveAudioStream.java#L49)
  - *Verification Result:* **Verified True.** Allocating 8 KiB native buffers (`MemoryUtil.memAlloc(frames * 4)`) every 42 ms relies on Minecraft's `SoundBuffer` to free the buffer. While functional, pooling these allocations would reduce native memory churn.

- 🎉 **`[praise]` Robust WAV & Vorbis Decoding Verification:**

### High-Confidence Findings (Score ≥ 80)

1. **Unconditional Dereference of `MusicClient.desiredState()` During Graph Submission**
   - **Confidence Score:** 85 / 100
   - **Reason:** Null dereference / Runtime client crash.
   - **Evidence:** [`GrooveEditorScreen.java:L305`](file:///D:/projects/Groove/src/client/java/com/mervyn/groove/client/ui/GrooveEditorScreen.java#L305)
     ```java
     boolean playing = MusicClient.desiredState().playing();
     ```
   - **Impact:** If a user clicks "Apply" or "Play/Stop" while reconnecting or when `desiredState()` is null (such as before the initial snapshot arrives), `MusicClient.desiredState()` returns `null`. This throws a `NullPointerException` that crashes the screen.
   - **Suggested Fix:** Add a null check matching `reloadSession()`:
     ```java
     var desired = MusicClient.desiredState();
     if (desired == null) {
         message = "No live session; reload before applying.";
         return;
     }
     boolean playing = desired.playing();
     ```
